# SimpleTunes 개발 결정 기록

## D-001 — 표시 이름은 SimpleTunes, 패키지는 유지

- 날짜: 2026-10-18
- 결정: 사용자에게 보이는 앱 이름은 SimpleTunes로 사용한다. `kr.co.hyomusic` applicationId와 upstream namespace는 호환성 위험 때문에 유지한다.
- 이유: 앱 이름은 현재 요구사항에 맞춰야 하지만 패키지 변경은 설치·업데이트·저장 데이터에 영향을 줄 수 있다.
- 영향: 리소스, 설정 화면, 문서는 SimpleTunes를 사용하고 과거 HyoMusic은 역사적 맥락으로만 남긴다.

## D-002 — NewPipe 기반 구조와 GPL 고지 보존

- 날짜: 2026-10-18
- 결정: NewPipe 앱/Extractor의 기존 플레이어와 스트리밍 호환성을 최대한 재사용하고 GPL-3.0-or-later 및 저작권 고지를 보존한다.
- 이유: 안정적인 검색·재생·백그라운드·MediaSession 기반을 새로 만들 필요가 없다.
- 영향: 최소 수정 원칙을 적용하고 upstream 변경과 SimpleTunes 전용 UI를 분리한다.

## D-003 — YouTube 스트리밍만 지원

- 날짜: 2026-10-18
- 결정: YouTube를 유일한 콘텐츠 소스로 사용한다. MP3/파일 다운로드, 라디오, 다른 플랫폼, 로그인·유료·DRM·접근 통제 우회는 구현하지 않는다.
- 이유: 부모님용 개인 스트리밍이라는 범위와 안전한 사용 범위를 지키기 위해서다.
- 영향: NewPipe 트리에 남은 원본 다운로드 코드는 사용자 기능으로 간주하지 않으며, 비공식 YouTube 추출의 정책·호환성 위험을 문서화한다.

## D-004 — 절제된 Premium Dark UI

- 날짜: 2026-10-18
- 결정: 짙은 남색·블루 계열, 큰 글자, 넓은 터치 영역, 고정 미니 플레이어와 작은 화면 스크롤을 사용한다. 네온·과도한 글로우·큰 배너·장식용 빈 공간은 배제한다.
- 이유: 이전 화려한 시안보다 부모님이 핵심 동작을 빠르게 이해하는 것이 우선이다.
- 영향: UI 작업은 기존 XML/ViewBinding 구조를 우선 활용하고, 실제 데이터가 없는 섹션은 더미 카드로 채우지 않는다.

## D-005 — 실제 기록과 fallback을 구분

- 날짜: 2026-10-18
- 결정: 최근 음악은 `HistoryRecordManager`, 재생목록은 `LocalPlaylistManager`/북마크 구조를 기준으로 한다. 기록이 없을 때의 네트워크 장르 검색은 사용자 기록으로 표시하지 않는다.
- 이유: 검색 결과를 개인 기록처럼 보여 주면 부모님이 앱 상태를 오해할 수 있다.
- 영향: 홈 빈 상태와 fallback 표시를 향후 우선 개선한다.

## D-006 — Gemini AI 재생목록 기능 유지

- 날짜: 2026-10-18
- 결정: 기존 Gemini 버튼과 API 연동을 유지한다. 사용자가 입력한 키로 자연어 요청을 처리하고, 생성된 검색어의 YouTube 결과를 NewPipe 재생목록 추가 흐름에 연결한다. 키는 저장소에 하드코딩하지 않는다.
- 이유: 최종 요구사항에서 Gemini 재생목록 기능과 음악 검색 기능을 유지하기로 확정했다.
- 영향: API 키·모델·쿼터·네트워크 오류를 사용자에게 표시하고 실기기 검증이 필요하다.

## D-009 — 중립적인 홈 탐색

- 날짜: 2026-10-18
- 결정: 국가·언어·특정 장르를 기본 추천으로 고정하지 않는다. 홈은 인기 음악 탐색, 최신 음악 탐색, 자유 장르 검색, 기록 기반 맞춤 추천, 즐겨찾기, 최근 재생으로 구성한다.
- 이유: 초기 사용자가 어떤 언어·문화권·장르를 선호할지 알 수 없고, 실제 순위 데이터 없이 인기/최신 순위를 표시하면 안 된다.
- 영향: 인기·최신은 YouTube 검색 탐색으로만 제공하며 공식 순위로 표현하지 않는다. 사용자 기록이 없으면 맞춤 추천은 빈 상태 안내를 표시한다.

## D-010 — 최근 기록이 없으면 섹션 숨김

- 날짜: 2026-10-18
- 결정: 최근 재생은 실제 `HistoryRecordManager` 기록 최대 3개만 표시하고 기록이 없거나 로드에 실패하면 섹션을 숨긴다.
- 이유: 검색 결과를 최근 재생처럼 보이는 더미 데이터로 표시하지 않기 위해서다.
- 영향: 초기 화면은 빈 카드 대신 중립적인 탐색 버튼 중심으로 표시된다.

## D-011 — 공식 API 없이 검색 후보를 보수적으로 점수화

- 날짜: 2026-10-18
- 결정: YouTube Data API 키와 공식 차트 연동이 없는 현재 프로젝트에서는 NewPipeExtractor 검색 결과만 수집한다. 라이브·Shorts·커버·노래방·모음집·리액션·리믹스를 제외하고, 장르/음악 근거·인증 채널·공식/오디오 신호·실제 조회수·확인된 업로드 날짜를 조합해 최대 20곡을 정렬한다.
- 이유: 존재하지 않는 공식 차트 엔드포인트나 조회수 증가율을 추측하면 추천 품질과 신뢰성을 더 악화시키기 때문이다.
- 영향: 결과는 “검색 기반 추천”으로 표시하며 공식 인기순위로 표현하지 않는다. 외부 장르 데이터베이스와 공식 API는 향후 자격 증명·쿼터·정책 검토 후 별도 추가한다.

## D-012 — 추천 결과 캐시

- 날짜: 2026-10-18
- 결정: 장르·지역·모드별 최대 20곡 결과를 SharedPreferences에 12시간 캐시하고, 캐시 오류는 재생을 막지 않는다.
- 이유: 같은 추천 화면을 반복해서 열 때 extractor 요청을 줄이고 네트워크 장애 때 마지막 정상 결과를 사용할 기반을 마련하기 위해서다.
- 영향: 실시간성은 최대 12시간 늦을 수 있고, 공식 순위 데이터가 아니므로 캐시 결과에도 검색 기반 표시를 유지한다.

## D-007 — GitHub manifest 기반 업데이트

- 날짜: 2026-10-18
- 결정: 기존 설정/WorkManager 흐름을 이용해 GitHub raw `update.json`의 version code/name/APK URL을 확인하고, 알림에서 브라우저 다운로드로 안내한다.
- 이유: 개인 debug APK 배포에 필요한 최소 기능이며 자동 설치 권한을 요구하지 않는다.
- 영향: manifest와 APK 주소를 함께 갱신해야 하며, debug 서명 자동 동의와 실제 기기 알림은 별도 검증한다.

## D-013 — Debug APK에도 GitHub 업데이트 메뉴 노출

- 날짜: 2026-10-18
- 결정: SimpleTunes의 Debug APK도 설정에서 GitHub manifest 수동 업데이트 확인을 사용할 수 있도록 업데이트 카테고리를 숨기지 않는다.
- 이유: 개인 설치용 Debug APK를 GitHub 브랜치로 배포하며, 기본 NewPipe의 공식 릴리스 서명 검사로 메뉴가 사라지는 문제가 있었다.
- 영향: Debug에서는 APK 자동 설치 대신 업데이트 알림의 브라우저 다운로드만 지원한다.

## D-014 — Gemini 안정 모델 우선 및 키 재입력 (대체됨)

- 날짜: 2026-10-18
- 결정: Gemini 요청은 `gemini-2.5-flash`를 우선하고 접근 가능한 fallback 모델을 시도하며, 인증/헤더 오류 시 저장 키를 삭제하고 다시 입력하게 한다.
- 이유: 모델 가용성은 계정·지역·시점에 따라 다르고, 잘못 저장된 키는 OkHttp 헤더 오류를 만들 수 있다.
- 영향: 이후 D-015 결정으로 앱의 키 입력 경로는 제거되었고, 모델 선택은 Cloud Run 프록시로 이동했다.

## D-015 — Gemini 자격 증명은 Cloud Run 서비스 계정으로 관리

- 날짜: 2026-10-18
- 결정: APK에서 Gemini API 키 입력·저장·전송을 제거하고, Cloud Run 프록시가 ADC로 Vertex AI Gemini를 호출한다. 서비스 계정 키 파일은 만들거나 저장소에 넣지 않는다.
- 이유: 개인 키가 APK 추출·재배포로 노출되는 것을 막고, 사용자의 Google Cloud 프로젝트와 할당량을 서버 측에서 관리하기 위해서다.
- 영향: Cloud Run 배포 URL과 런타임 서비스 계정의 Vertex AI User 권한이 필요하다. 공개 엔드포인트는 개인 설치용이며 호출량 제한·인증을 추가하기 전에는 공개 배포를 확대하지 않는다.

## D-016 — Gemini 프록시를 개인용 Cloud Run에 배포

- 결정: Gemini 재생목록 요청은 `https://simpletunes-gemini-5df6beotgq-du.a.run.app/v1/playlist`로 보낸다. Cloud Run은 Vertex AI `gemini-2.5-flash`를 서비스 계정 ADC로 호출한다.
- 이유: APK에 Gemini 키를 포함하지 않고 기존 버튼 기능을 실제로 동작시키기 위해서다.
- 영향: 백엔드가 공개 개인용 엔드포인트이므로 비용·쿼터·남용 위험을 모니터링해야 한다. APK에는 비밀 자격 증명이 포함되지 않는다.

## D-008 — 초기 맥락 동기화 단계는 문서만 변경

- 날짜: 2026-10-18
- 결정: 2026-10-18 초기 맥락 동기화 단계에서는 UI·재생·업데이트 코드를 수정하지 않고 현황 조사와 공통 문서 체계만 추가했다.
- 이유: 기존 사용자 변경 사항과 작동 중인 스트리밍 기능을 보호하면서 다음 개발의 기준점을 먼저 확정하기 위해서다.
- 영향: 발견된 문제는 `DEV_STATUS.md`와 다음 우선순위에 남기고 후속 작업에서 최소 수정한다.
